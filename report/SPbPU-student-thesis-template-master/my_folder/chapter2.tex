\section{Модуль ввода/вывода и пакетной обработки JSON (com.ipfilter.service)}

\subsection{ Методы класса JsonHandler}
\subsubsection{Метод loadInput}
\texttt{public InputData loadInput(String filePath) throws IOException}
Назначение: загрузка входных данных из JSON-файла с поддержкой classpath и файловой системы.
Вход: filePath - путь к JSON-файлу (относительный или из classpath)
Выход: InputData - объект с полями blacklist и checkIps
Логика работы: метод последовательно пытается загрузить файл: (1) из classpath через getResourceAsStream(), (2) как обычный файл через new File(), (3) из корня проекта. При неудаче генерируется IOException.
Исключения: IOException при ошибке чтения или некорректном формате JSON.

\subsubsection{Метод saveOutput}
\texttt{public void saveOutput(String filePath, OutputData data) throws IOException}
Назначение: запись результата проверки в выходной JSON-файл.
Вход: filePath - путь к выходному файлу, data - объект OutputData с результатами проверки
Выход: выходной файл в формате JSON.
Логика работы: выполняется сериализация объекта через ObjectMapper.writerWithDefaultPrettyPrinter().writeValue().
Исключения: IOException при ошибке записи.

\subsection{Методы класса FilterService}
\subsubsection{Метод loadDataFromFile}
\texttt{public void loadDataFromFile(String filePath) throws Exception}
Назначение: загрузка чёрного списка IP-адресов из JSON-файла в обе структуры данных.
Вход: filePath - путь к JSON-файлу с blacklist
Выход: отсутствует (данные загружаются во внутренние фильтры)
Логика работы: вызывается jsonHandler.loadInput(), затем каждый IP из blacklist добавляется в HashSetFilter и BloomFilter.
Исключения: IOException при ошибке чтения файла.

\subsubsection{Метод processAndCompare}
\texttt{public OutputData processAndCompare(List<String> ipsToCheck)}
Назначение: проверка списка IP-адресов обоими алгоритмами с формированием отчёта.
Вход: ipsToCheck - список IP-адресов для проверки
Выход: OutputData - объект с результатами, статистикой и рекомендацией
Логика работы: замеряется время выполнения для каждого алгоритма, для каждого IP вызывается contains() в обоих фильтрах, формируется список FilterResult с полями hashSetResult, bloomFilterResult, match, вычисляется статистика (память, время, вероятность False Positive), генерируется рекомендация по выбору алгоритма
Исключения: не генерируются.

\subsubsection{Метод generateRecommendation}
\texttt{private String generateRecommendation(FilterStatistics stats)}
Назначение: формирование текстовой рекомендации по выбору алгоритма.
Вход: stats - объект статистики фильтрации
Выход: строка с рекомендацией
Логика работы: сравнивается память HashSet и Bloom Filter. Если Bloom Filter экономит память - рекомендуется он, иначе - HashSet.


\section{Методы модуля фильтрации (com.ipfilter.filter)}
\subsection{Методы интерфейса IpFilter}
Методы интерфейса IpFilter:
\begin{itemize}
    \item add(Sting ip)
    \item contains(String ip)
    \item long getMemoryUsageBytes()
    \item clear()
    \item getSize()
\end{itemize}

Назначение: основа для всех реализаций фильтров IP-адресов.

\subsection{Методы класса HashSetFilter}
\subsubsection{Метод add}
\texttt{public void add(String ip)}
Назначение: добавление IP-адреса в HashSet.
Вход: ip - строка IP-адреса
Логика работы: вызывается blacklist.add(ip) после проверки на null и пустую строку.
\subsubsection{Метод contains}
\texttt{public boolean contains(String ip)}
Назначение: проверка наличия IP в HashSet.
Вход: ip - строка IP-адреса
Выход: true если IP найден, false в ином случае
Логика работы: вызывается blacklist.contains(ip). Точность 100\%.
\subsubsection{Метод getMemoryUsageBytes}
\texttt{public long getMemoryUsageBytes()}
Назначение: оценка потребления памяти.
Выход: приблизительный размер в байтах (размер * 100 байт на элемент)

\subsection{Методы класса BloomFilter}
\subsubsection{Метод add}
\texttt{public void add(String ip)}
Назначение: добавление IP-адреса в Bloom Filter.
Вход: ip - строка IP-адреса
Логика работы: для каждой из k хэш-функций вычисляется индекс в битовом массиве и устанавливается бит в 1.
\subsubsection{Метод contains}
\texttt{public boolean contains(String ip)}
Назначение: проверка наличия IP в Bloom Filter.
Вход: ip - строка IP-адреса
Выход: true если IP возможно есть (False Positive возможен), false если точно нет
Логика работы: для каждой хэш-функции проверяется бит. Если хотя бы один бит = 0 — элемент точно отсутствует.
\subsubsection{Метод getHash}
\texttt{private int getHash(String ip, int iteration)}
Назначение: вычисление хэш-значения для IP-адреса.
Вход: ip — строка IP-адреса, iteration — номер хэш-функции (0..k-1)
Выход: положительное целое число (индекс в битовом массиве)
Логика работы: используется CRC32 с добавлением итерации и seed для детерминированности. Применяется Math.abs() для гарантии положительного значения.
\subsubsection{Метод getFalsePositiveProbability}
\texttt{public double getFalsePositiveProbability()}
Назначение: расчёт вероятности False Positive.
Выход: вероятность от 0.0 до 1.0
Логика работы: формула (1 \- e\^(\-kn\/m))\^k, где k — число хэш-функций, n — число элементов, m — размер битового массива.

\texttt{public static void main(String[] args)}
